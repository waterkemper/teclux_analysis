# Gerar Contrato a partir do Orçamento

Status: ready-for-agent
Label: ready-for-agent

## Problem Statement

O Laravel já possui um botão e um serviço para gerar Contrato a partir do Orçamento, mas a implementação é parcial e diverge do Delphi. O Contrato é criado na Situação errada, recebe poucos campos financeiros, Produtos são copiados sem seus dados comerciais e várias partes do agregado são omitidas: Cliente, dados cadastrais, entrega, frete, séries, Serviços, parcelas completas, estoque, Qualidade da Venda, Atendimento e Questionário.

Como ainda não existe Cadastro de Contratos no Laravel, o fluxo não deve redirecionar para uma tela inexistente. A entrega precisa gerar corretamente o Contrato, vincular o Orçamento e mostrar persistentemente o número na própria tela, com atomicidade e idempotência.

## Solution

Completar o gerador Laravel existente para reproduzir as regras funcionais comprovadas do Delphi. Antes de gerar, revalidar o Orçamento persistido, endereço de entrega, estoque parametrizado, Plano e vencimentos, Cliente, Permissão e Qualidade da Venda. Quando não houver Cliente cadastrado, criar e vincular um Cliente com os dados do Orçamento, desde que sejam suficientes.

Em uma operação atômica e concorrente segura, consumir o número, criar o Contrato em `O — Orçado`, copiar cabeçalho, dados cadastrais/comerciais, Produtos, séries, Serviços e Parcelas, integrar Atendimentos essenciais, marcar o Orçamento como `T` e vincular o número. Após commit, executar o fluxo durável de Questionário. Atualizar a tela sem redirecionamento e exibir o número gerado.

## Implementation Decisions

- The Cursor/SpecKit execution environment must treat the consolidated Delphi evidence in the handoff as authoritative input and inspect only Laravel. Missing or ambiguous Delphi evidence becomes an explicit blocker returned to the analysis workspace; it must not be inferred from images, UI behavior or inaccessible source paths.

- Extend the existing controller/service/repository path; do not create a second generator.
- Require persisted Orçamento Situação `A`, valid date, Products, exactly one selected Plan and valid installments.
- Validate complete delivery address when delivery is configured.
- Respect `Produtos no orçamento com estoque` and calculate Product fulfillment authoritatively at generation time.
- Apply Sales Quality/Credit Analyst authorization using the existing sensitive-operation infrastructure.
- Require a Cliente on every generated Contract. Create/link one from Orçamento data only when required fields pass and deduplication is safe.
- Create Contract in `O`; update Orçamento to `T` and set its Contract number.
- Copy the complete commercial snapshot rather than mutable references alone.
- Copy Product lines, serials, Services and installments with all proven fields.
- Preserve Atendimento conversion/link behavior and the existing Questionnaire application contract.
- Keep essential writes in one database transaction where technically possible; make post-commit Questionnaire durable and resumable.
- Lock the Orçamento and enforce a database-level uniqueness/invariant between Orçamento and Contract.
- Make retries return the existing number without repeating Cliente, Atendimento, Questionário or item writes.
- Do not redirect after success. Refresh authoritative Orçamento data, show the number and disable generation.
- Treat logged-in Usuário, Credit Analyst, vendedor and Atendimento responsible user as distinct actors.

## Testing Decisions

- Primary seam: post the real generation command and assert Contract aggregate, Cliente, Orçamento transition, integrations and response/flash number.
- Test observable database and UI behavior, not private repository methods.
- Expand the existing Orçamento generation Feature test as prior art.
- Cover every precondition and parameter branch.
- Cover existing Cliente, automatic Cliente, insufficient data and duplicate identity.
- Cover Credit Analyst required/not required, success, cancel, invalid credentials and wrong role.
- Cover complete field parity for header, Products, serials, Services and installments.
- Cover stock race, concurrent requests, repeated request and failure rollback at each major stage.
- Cover Atendimento exactly once and Questionnaire create/resume exactly once after commit.
- Cover success UI, no redirect, persistent number and disabled button.

## Out of Scope

- Implementing Cadastro or Consulta de Contratos.
- Redirecting to, opening or editing the generated Contract.
- Faturar, Reservar, imprimir or cancel the Contract.
- Changing the Contract lifecycle beyond initial `O`.
- Implementing in this analysis workspace or altering Delphi.

## Further Notes

- CONFIRMADO: Delphi copies a substantially larger aggregate than the current Laravel repository.
- CONFIRMADO: Delphi creates Cliente when absent, records Atendimento, sets Contract `O`, Orçamento `T`, copies items and triggers Questionnaire.
- DIVERGENTE: current Laravel creates Contract `A` and copies only minimal fields.
- NÃO LOCALIZADO: current Laravel generation integrations for Cliente, Atendimento, Sales Quality, stock policy, serials, Services and Questionnaire.
- DECISÃO NOVA: generation is idempotent and ends on the same Orçamento screen showing the number.
